# Подписка для ducker

ducker работает с обычной подпиской mihomo: если ваша панель уже выдаёт конфиг клиентам Clash
Meta или FlClash, для ducker ничего менять не нужно. Ниже — что приложение отправляет, что
принимает в ответ и как сделать для него отдельный ответ.

## Какие панели подходят

| Панель | ducker получает конфиг mihomo | Название, трафик, срок | Объявление | Лимит устройств | Свои заголовки ducker |
|---|---|---|---|---|---|
| Remnawave | по умолчанию | да | да | да | свои заголовки ответа |
| PasarGuard | по умолчанию | да | да | да | свои заголовки ответа |
| Marzban | по умолчанию | да | — | — | — |
| Marzneshin | добавьте правило `^mihomo` → `clash-meta` выше последнего или дайте ссылку `…/clash-meta` | да | — | — | — |
| 3x-ui | включите подписку Clash и её автоопределение или дайте ссылку `/mihomo/<subid>` | да | да | да | — |
| Hiddify | дайте ссылку `…/clashmeta/` | да | — | — | — |

Сверено с кодом панелей в ноябре 2026 года: Remnawave 3.4.8, PasarGuard 5.6.0, Marzban 0.8.4,
Hiddify 14.2.0. Безлимитный тариф Hiddify показывается далёкой датой. Если панель отдаёт простой
список ссылок, ducker всё равно подключится: он поставит узлы во
[встроенный шаблон](template.md).

## Что приходит от приложения

Запрос подписки идёт с заголовком

```
User-Agent: mihomo/<версия ядра> ducker/<версия приложения> (android)
```

Он начинается с `mihomo/`, поэтому панель, которая выбирает формат ответа по `User-Agent`,
отдаёт конфиг mihomo — в Remnawave срабатывает обычное правило для клиентов mihomo. Слово
`ducker` в той же строке позволяет отличить приложение от остальных, последнее слово называет
платформу. Наборы правил и провайдеры узлов, которые скачивает конфиг, запрашиваются так же, как
это делает mihomo: с заголовком `header:` самого провайдера, иначе с `global-ua` конфига, и без
данных устройства.

Вместе с запросом уходят данные устройства — идентификатор, версия Android и модель. О них и о
лимите устройств — на странице [«Устройства и лимит»](devices.md).

## Что приложение принимает

| Что пришло по ссылке | Что делает ducker |
|---|---|
| Конфиг mihomo, который проходит проверку ядра | Применяет как есть. Ключи конфига приложение не переписывает. |
| Список ссылок `vless://`, `vmess://`, `ss://`, `trojan://` и подобных, открытым текстом или в base64 | Подставляет узлы во [встроенный шаблон](template.md). |
| Конфиг mihomo с ошибкой | Новая подписка: узлы из него идут во [встроенный шаблон](template.md), человек видит карточку с текстом ошибки. Уже добавленная — работает на прежнем конфиге. Подробнее — ниже. |
| Что-то другое или конфиг без узлов | Новая подписка не добавляется, человек видит причину. Уже добавленная — работает на прежнем конфиге. |

**Ошибка при обновлении не оставляет человека без VPN.** Новый конфиг сначала скачивается и
проверяется ядром и только потом заменяет рабочий. Если проверку он не прошёл — пришёл конфиг с
ошибкой, страница сервера вместо подписки, пустой ответ или конфиг без единого узла, — у человека
остаётся прежний конфиг, VPN продолжает работать. На вкладке «Подписки» появляется карточка
«Не удалось обновить» с причиной и текстом ошибки ядра, который он может переслать вам.

**Ошибка в конфиге новой подписки.** Рабочего конфига у человека ещё нет, поэтому отказа он не
получает. Если файл читается и в нём есть раздел `proxies`, ducker берёт узлы оттуда, подставляет
во встроенный шаблон и показывает на главной карточку «В конфиге провайдера ошибка…» с кнопкой
«Скопировать ошибку» — чтобы человек переслал её вам. Узел, который ядро собрать не может,
пропускается. Маршрутизация при этом — шаблона, не ваша. Исправили конфиг — при следующем
обновлении он применится, карточка исчезнет. Узлы из `proxy-providers` так не берутся; если узлов
достать не удалось, подписка не добавляется.

Ссылка может переадресовывать на другой адрес — приложение идёт следом, не больше десяти раз.

**Зашифрованная подписка.** Remnawave умеет шифровать подписку ключом age в правилах ответа.
Скачав такую подписку, ducker объясняет это в окне добавления и показывает поле «Ключ
расшифровки» для ключа, который начинается с `AGE-SECRET-KEY-`. Передавайте ключ отдельно от
ссылки.

Когда VPN включён, подписка обновляется по правилам профиля — обычно через узел; при выключенном
VPN запрос идёт напрямую. Если не ответил ни один адрес подписки, ducker пробует ещё раз напрямую и
через узел самой подписки (см. [«Зеркала подписки»](headers.md#зеркала-подписки)).

## Список для мобильной сети

На странице **«Возможности → Мобильная сеть»** ducker переключается на выбранную подписку и
список узлов, когда телефон уходит с Wi-Fi. Этот список можно заполнить за пользователей:
соберите узлы, которые работают на мобильном интернете (например, через белые списки
операторов), в обычную группу и назовите её в ключе верхнего уровня `ducker`:

```yaml
ducker:
  mobile-group: LTE

proxy-groups:
  - name: Proxy              # главная группа: первая группа select, её показывает «Главная»
    type: select
    proxies: [NL-1, DE-1, LTE-1, LTE-2]
  - name: LTE
    type: fallback           # любой тип; fallback подходит и другим приложениям
    url: https://www.gstatic.com/generate_204
    interval: 300
    hidden: true             # по желанию: не показывать на вкладке «Прокси»
    proxies: [LTE-1, LTE-2]
```

- **Список** — узлы группы, которые есть и в главной группе, в вашем порядке: ducker
  переключает узел главной группы, проверяет список сверху и берёт первый, который отвечает.
  Если в главной группе нет ни одного из этих узлов, но в неё добавлена сама группа из
  `mobile-group`, ducker выбирает её. За выбор узла отвечают настройки этой группы.
- **Когда срабатывает.** Подписка с ключом сама включает «Переключение по сети», пока
  пользователь не настраивал страницу. Его собственные настройки не заменяются. Если таких
  подписок несколько, страницу настраивает первая скачанная.
- **Обновления.** Пока включён «Список провайдера», каждое обновление приносит ваш текущий
  список. Если пользователь правит список, переключатель выключается; включив его, он вернёт
  ваш список. Ответ без ключа очищает список и выключает переключение; ключ вернулся —
  переключение включается снова.
- **`ducker-override-user: on`** при каждом обновлении снова включает «Список провайдера» и
  переключение, если только пользователь не выбрал для мобильной сети другую подписку.
  Страница не закрыта: пользователь может выключить переключение до следующего обновления.
- **Если YAML изменить нельзя,** пришлите имя группы в заголовке
  [`ducker-mobile-group`](headers.md); группа должна быть в конфиге. Ключ главнее заголовка.
  На телевизоре не применяется.

Другие приложения видят обычную группу и ключ пропускают. Конфиг не переписывается.

## Заголовки ответа

Общепринятые заголовки подписки ducker понимает так:

| Заголовок | Что делает |
|---|---|
| `profile-title` | Имя подписки. |
| `profile-update-interval` | Как часто обновлять подписку, в часах. |
| `subscription-userinfo` | Израсходованный трафик, лимит и срок — на главной и на карточке подписки. |
| `subscription-refill-date` | Когда обнулится счётчик трафика, время в секундах Unix. |
| `support-url` | Кнопка «Поддержка»; она же — «Продлить», если не задан `ducker-buy-url`. |
| `profile-web-page-url` | Страница провайдера; она же — кнопка «Продлить», если не заданы ни `ducker-buy-url`, ни `support-url`. |
| `announce` | Объявление на главной. |

Текст с кириллицей передаётся как `base64:<…>` в UTF-8.

Название, логотип и поведение приложения настраиваются
[заголовками `ducker-*`](headers.md).

## Отдельный ответ для ducker в Remnawave

Чтобы заголовки `ducker-*` и свой шаблон получал только ducker, заведите в правилах ответа
подписки отдельное правило по слову `ducker` в `User-Agent` и поставьте его выше общего правила
для клиентов mihomo. В выгрузке правил оно выглядит так:

```json
{
  "name": "Mihomo — ducker (Android)",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "CONTAINS",
      "value": "ducker",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "headers": [
      { "key": "ducker-brand-name", "value": "Pond" },
      { "key": "ducker-brand-logo", "value": "https://example.com/logo.png" },
      { "key": "ducker-buy-url", "value": "https://example.com/renew" }
    ],
    "subscriptionTemplate": "Default"
  }
}
```

Названия полей — как в выгрузке правил Remnawave на октябрь 2026 года; если панель обновилась,
сверьтесь с её документацией. Код панели править не нужно.

<details markdown="1">
<summary>Полный пример со всеми заголовками <code>ducker-*</code></summary>

Оставьте нужные заголовки и подставьте свои значения. `LTE` должно совпадать с именем группы в
конфиге. Если группа задана в YAML через `ducker.mobile-group`, применяется она.
[Значения и действие заголовков](headers.md).

```json
{
  "name": "Mihomo — ducker (Android)",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "CONTAINS",
      "value": "ducker",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "headers": [
      { "key": "ducker-brand-name", "value": "Pond" },
      { "key": "ducker-brand-logo", "value": "https://example.com/logo.png" },
      { "key": "ducker-buy-url", "value": "https://example.com/renew" },
      { "key": "ducker-global", "value": "on" },
      { "key": "ducker-local-proxy", "value": "on" },
      { "key": "ducker-share", "value": "on" },
      { "key": "ducker-override-user", "value": "off" },
      { "key": "ducker-mobile-group", "value": "LTE" },
      { "key": "ducker-mirrors", "value": "sub2.example.com, sub3.example.org" }
    ],
    "subscriptionTemplate": "Default"
  }
}
```

## Ссылка в одно касание

```
ducker://install-config?url=<ссылка подписки>&name=<имя>&mirror=<запасной>&mirror=<запасной>
```

Открывает в приложении окно добавления подписки с уже вставленной ссылкой. Скачивается подписка
только после того, как человек нажмёт «Добавить». Ссылку подписки внутри нужно закодировать
(`https%3A%2F%2F…`). Так же открываются ссылки `clash://install-config` и
`clashmeta://install-config`.

`name` необязателен: имя подписки, пока провайдер не присылает `profile-title`. Как только
заголовок пришёл, показывается его название; имя, которое человек дал подписке сам, главнее обоих.
Без них на карточке — домен ссылки.

`mirror` необязателен и повторяется: каждый — запасной адрес, записанный так же, как в
[`ducker-mirrors`](headers.md#зеркала-подписки), — домен без `https://` и пути или полная ссылка
`https://…`. Они пробуются при этом первом скачивании, когда сама ссылка уже заблокирована. Дальше список приходит
из заголовка: ответ самой ссылки без него их убирает. Когда человек делится подпиской QR-кодом
или отправляет её на телевизор, ducker передаёт и её текущие зеркала.

`key` — необязательный ключ расшифровки подписки (`AGE-SECRET-KEY-…`). В примере выше он опущен.
При добавлении подписки он попадает в поле «Ключ расшифровки». ducker добавляет его сам,
когда человек делится зашифрованной подпиской QR-кодом или отправляет её на телевизор.
Ссылка с ключом открывает подписку без всего остального,
поэтому на общей странице ключ лучше передавать отдельно, как сказано выше.
